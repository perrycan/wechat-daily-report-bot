# 架构设计

## 五层架构

项目把"微信操作 → 业务逻辑 → 对外接口 → 模型 → 指令触发"分成清晰的五层，每层单一职责，便于测试与替换：

```
┌──────────────────────────────────────────────────────────────────┐
│ 指令层   聊天口令「接龙/催办/汇总/状态」→ /bash 命令 → CLI/API       │  openclaw_command_router.py
│          （经 scripts/ 的网关补丁，可对接微信 / Telegram）           │
├──────────────────────────────────────────────────────────────────┤
│ 接口层   FastAPI :8000  +  schedule 定时线程（30s 轮询）            │  api_server.py
│          /jielong /cuiban /huizong /status /send_msg /rules        │
├──────────────────────────────────────────────────────────────────┤
│ 业务层   发接龙 / 催办 / 汇总；会话切换、消息解析、比对、发送、回退    │  bot_core.py
├──────────────────────────────────────────────────────────────────┤
│ 模型层   每次汇总前热加载规则 → 调 LLM → 生成管理口径汇总            │  llm_summary.py
├──────────────────────────────────────────────────────────────────┤
│ 微信层   窗口切换、原生接龙发起、@、聊天记录读取                      │  wxauto（开源）/ wxautox4（商业，微信4.x）
└──────────────────────────────────────────────────────────────────┘
              config.py（群/花名册/时间/文案）
              rules/summary_fixed_rules.md（热加载的汇总 Prompt）+ summary_rules.txt（补充规则）
```

## 关键设计决策（问题 → 做法 → 价值）

### A. 汇总 Prompt 外置 + 运行时热加载 ⭐
- **问题**：汇总口径会频繁调整，写死在代码里每次都要改代码、重启、发版。
- **做法**：规则放在 `rules/summary_fixed_rules.md`；**每次执行汇总前重新读取**，用当次最新内容作为 system prompt。支持 `.md/.txt/.docx` 三种格式，路径可由 `LLM_FIXED_RULES_FILE` 覆盖。
- **价值**：规则今天改、今天生效，无需重启、无需发版。这是项目可持续运营的基石。

### B. 先按"当天日期"搜索定位接龙，而非滑屏
- **问题**：微信长消息会折叠，直接滑屏找接龙容易找错或读到历史旧消息，导致识别错、误催。
- **做法**：打开群「聊天记录」搜索窗口 → 输入当天日期定位 → 双击复制全文；失效时降级为"仅遍历当天聊天记录"。
- **价值**：提高识别准确率，降低误催风险。

### C. 用微信原生接龙 + 原生 @，不伪造文本
- **问题**：纯文本伪造 `@xxx` 不是真提醒，自造接龙也无自动编号、无法可靠解析。
- **做法**：`#接龙` → 微信「编辑接龙表格」发起真接龙卡片；@ 用微信原生能力。
- **价值**：真提醒、真接龙卡、可解析。

### D. 定时与口令并存
- **问题**：日常有固定时间，但常有临时补跑需求。
- **做法**：`schedule` 跑工作日日常；聊天口令负责随时触发，不受时间限制。
- **价值**：稳定性与灵活性兼得。

### E. 汇总私发领导 + 群内只回执
- **问题**：汇总是给管理者看的，误发到群会泄露/尴尬。
- **做法**：发送时强制 `who=领导`，会话切换仅作前置、失败不阻塞；群里只发一句确认回执。
- **价值**：杜绝误发到群。

## 数据流（汇总）

```
群最新接龙全文 ──→ llm_summary.summarize()
   ├─ system = 固定规则(md/docx，每次重读) + summary_rules.txt（补充）
   ├─ user   = 接龙原文 + 已接龙/未接龙/请假统计
   ├─ 模型链 = gpt-5.4 →(区域不可用/失败回退) gpt-5.4-mini → deepseek-chat-v3
   └─ 输出 ──→ 分片私发领导 ──→ 群内发回执
```

## 后端选择策略

- 自动探测：检测到微信 4.x 优先 `wxautox4`，否则用 3.9.x 线的 `wxauto`；可用 `BOT_WECHAT_BACKEND` 强制。
- 多后端导入按优先级降级，第一个可用即用；初始化失败时给出可读的中文诊断（未激活 / 未登录 / 无效窗口句柄）。

## 技术选型理由

| 维度 | 选择 | 理由 |
|---|---|---|
| 接口框架 | FastAPI + uvicorn | 轻量、自带 `/docs`、便于口令网关调用 |
| 定时 | `schedule` + 守护线程 | 简单够用 |
| 工作日判断 | `chinese-calendar` | 处理法定节假日与调休，而非简单"周一到周五" |
| LLM | OpenRouter（默认）/ DeepSeek | 统一网关、多模型可回退 |
| 规则载体 | Markdown（也支持 docx） | 业务方可直接编辑、GitHub 可渲染、便于 diff |
| GUI 模拟 | pyautogui + pyperclip + uiautomation | 处理原生弹窗、复制粘贴、控件定位 |

更多健壮性细节见 [PITFALLS.md](PITFALLS.md)；汇总规则方法论见 [SUMMARY_RULES.md](SUMMARY_RULES.md)。
