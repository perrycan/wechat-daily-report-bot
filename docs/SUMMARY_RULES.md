# 汇总规则与 Prompt 工程

← 返回 [README](../README.md)

> 本项目真正难复刻的不是代码，而是"如何把 10 个人的工作流水账，汇总成领导想看的管理口径日报"的**领域规则**。规则不是拍脑袋写的，而是用一套**数据驱动的迭代方法**逐日提炼出来的。
> 规则全文见 [`rules/summary_fixed_rules.md`](../rules/summary_fixed_rules.md)（已脱敏），它会被 `llm_summary.py` 在每次汇总前热加载。

## 1. 规则迭代方法论（核心思想）

把"调 Prompt"变成一个**有标注、有对照、可追溯**的工程：

```
每日： 接龙原文  ──→  ① LLM 自动汇总（基线）
                 └─→  ② 领导人工汇总（Ground Truth / 标准答案）
       ③ 人工逐条标注：LLM 哪条不对、为什么、领导为何那样改
                 ↓
       ④ 把"为什么"沉淀成一条新规则，写回固定规则文件
                 ↓
       下一天 LLM 汇总质量提升 → 再对照 → 再补规则（收敛）
```

用一张"逐日对照表"承载：`日期 | 接龙原文 | LLM 汇总 | 领导人工汇总(标准答案) | 当日提炼的新规则`。
当汇总质量不达预期时，**不要凭感觉改 Prompt**——拿当天原文对照领导期望版本，定位错点、归纳成可执行规则、写回规则文件即可（热加载即时生效）。

## 2. 固定分类框架（5 类，排序固定）

LLM 必须把零散接龙打散、按事项重归并，输出到这 5 个固定类目（无内容的类目跳过）：

| 序 | 类目 | 涵盖（示例，已脱敏） |
|---|---|---|
| 一 | **DSMP** | 采购平台/系统接口/供应商管理功能、需求/改善单/测试/bug/上线；合同、供应商编码、价格、索赔、电子签等 |
| 二 | **流程** | 制度、流程、授权、权责、节点、审批规则；流程梳理/修订/对比分析 |
| 三 | **应审** | 客户稽核/审核对应、资料收集/补充/回复、调查表、资质证明；重点体现审核对象、资料准备、回复、进度 |
| 四 | **系统&项目** | 并购项目（强兆/强荣等）、系统/流程切换融合、项目推进、专项汇报、BI 报表、AI 项目、智能工厂评审 |
| 五 | **培训&会议&其他类** | 绩效、人才盘点、PPT 汇报、培训、会议、宣传；**兜底类**——有结果产出但不属于前四类的都归这里 |

**输出格式**：每类下 `1、2、…`；同一事项多个子动作用 `①②③`；系统&项目类按"项目名："前缀分组。只输出结果、不复述姓名、不照抄原顺序、空类目不输出。

## 3. 高频规则及其"为什么"（精华）

**过程 vs 结果（最核心）**
- 日报只记**当天有结果产出**的事项；纯过程（答疑、沟通、待提交、待确认…）不写，等有结果再写。
- 判断金句：**"去掉这条，汇总的信息价值是否减少？不减少就删。"**
- 标准格式："事项，结果"（如`现货采购作业规范改版申请，已完成审批`）。
- ⚠ 结果优先级最高：原文出现"已完成/已确认/已输出"等结果词，即使看着像过程也必须写入。
- ⚠ 不可编造：原文只说"做了什么"未提结果，不能自行补"已完成"。

**分类互斥**：每条事项只归一类，严禁同时出现在两个分类。

**并购项目（最高优先级，先于一切分类规则）**
- 出现并购关键词 → 一律归"系统&项目"，即使内容含其他分类字眼。
- ⚠ 两个并购项目（如**强兆**与**强荣**）是完全不同的公司，严禁混淆/合并，各自用项目名前缀。

**合并与拆分**
- 合并：多人写本质相同事项（如同一智能工厂评审的不同场景）→ 合并为一条，取信息量更大的版本。
- ⚠ 关键词路由：出现"领航/智能工厂"等关键词 → 必归对应项目类，不归采购类。
- 拆分：应审类中不同工厂/客户的审核**必须拆成独立条目**，严禁合并（不同审核对象 = 不同事项）。

更细的特定人/特定事项归属规则、业务术语表、工厂清单、人员负责项目对照表，均在 [`rules/summary_fixed_rules.md`](../rules/summary_fixed_rules.md) 中（全部脱敏）。

## 4. 规则维护机制

1. **改固定规则**（推荐）：编辑 `rules/summary_fixed_rules.md`，下次汇总即生效（热加载）。
2. **改补充规则**：编辑 `summary_rules.txt`，或经 `POST /rules` 动态写入；与固定规则配合，冲突以固定规则为准。
3. **飞书文档**（可选）：配置 `FEISHU_*` 后改从飞书在线文档拉规则，便于多人协作维护。
